`window.location.href` 是**浏览器原生的页面级跳转**，而 React Router 是**应用内的组件级导航**。在 Electron 打包后，前者会出错，根源在于**文件系统的路径变化**和**客户端路由状态丢失**。

### 🔍 核心区别

| 特性                | `window.location.href`  | React Router (`useNavigate` / `Link`) |
| ----------------- | ----------------------- | ------------------------------------- |
| **本质**            | 浏览器 **URL 跳转**          | React 应用内的 **组件渲染切换**                 |
| **是否刷新页面**        | **是** (整页刷新，重绘页面)       | **否** (仅替换组件，无刷新)                     |
| **是否触发 HTTP 请求**  | **是** (向服务器请求新页面)       | **否** (使用前端已加载的资源)                    |
| **是否保留 React 状态** | **否** (页面刷新，状态全部丢失)     | **是** (组件切换，状态保留)                     |
| **主要用途**          | 跳转到**外部链接**或**完全不同的网站** | 在**单页应用 (SPA)** 的不同**视图**间切换          |
### 为什么在 Electron 打包后 `window.location.href` 会出错？

在 Electron 开发环境 (`localhost:3000`) 中，`window.location.href = '/about'` 能正常工作，因为开发服务器会处理这个请求并返回对应的 HTML。但在打包后 (`file://` 协议下)，它就会出错。核心原因有两个：

1. **文件系统路径无法匹配 URL**：打包后，应用运行在 `file://` 协议下。你的应用实际上是一个 `index.html` 文件。当执行 `window.location.href = '/about'` 时，Electron 会试图在文件系统中寻找一个名为 `about` 的文件夹或文件。因为 `about` 不是一个真实的文件或文件夹，所以会返回 `404 Not Found` 或空白页。
    
2. **破坏了 SPA 路由规则**：React Router 管理的是**前端路由**，它依赖于 **`history.pushState`** API 来改变 URL 而不刷新页面。使用 `window.location.href` 跳转时，会绕过 React Router 的控制，直接向底层文件系统发起请求，导致路由失效。
